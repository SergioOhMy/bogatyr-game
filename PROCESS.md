# PROCESS.md — лог сессии

## Задача
Пользователь прислал скриншот из прошлого боя: на поле одновременно два
«Алёши Поповича» — один в дружине (целый), другой у противника (раненый).
Просьба: посмотреть, разово ли это, и починить если нужно. Модель: Sonnet 5.

## Что сделано

### Диагностика
Прочитан `js/ui.js -> renderBattlefield()`. Очистка устаревших DOM-карточек
бойцов сравнивала id элемента с id, взятыми из ОБЕИХ команд сразу
(`[...state.playerTeam, ...state.enemyTeam]`), а не с id команды именно того
контейнера (`#player-team` / `#enemy-team`), где лежит элемент.

Сценарий бага: герой был в дружине игрока в бою N (карточка осела в
`#player-team`), а в бою N+1 тот же герой случайно достался боту. Его id
формально "числится" в объединении (через enemyTeam) → старая карточка в
`#player-team` не удаляется, застывает на последнем известном HP, а в
`#enemy-team` рисуется вторая, настоящая карточка. Два визуально разных
бойца с одним именем одновременно — ровно то, что на скриншоте. Не разовый
глюк, а воспроизводимый баг рендера.

### Воспроизведение и фикс
- Воспроизведено напрямую через `renderBattlefield()` с подставными данными
  (бой 1: Алёша в дружине 112/112 → бой 2: Алёша у бота 37/112, дружина без
  него) - подтверждена карточка-призрак в `#player-team`.
- Исправлено: очистка теперь сверяет каждый контейнер с id команды именно
  этого контейнера, а не с объединением обеих.
- Тот же тест после фикса: призрака нет, ровно один боец на верной стороне.
