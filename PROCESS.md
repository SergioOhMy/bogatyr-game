# PROCESS.md — лог сессии

## Задача
QA-тестирование игры на уровне сеньор-тестировщика + поиск и удаление мёртвого кода.

## Что сделано

### 1. Статический анализ / мёртвый код
- Скрипты-сканеры (неиспользуемые exports, CSS-классы, HTML id vs getElementById) — прогнаны по всему `js/*.js`, `index.html`, `css/style.css`.
- Найдено и удалено: мёртвое CSS-правило `.promo-btn` + `.promo-btn:hover` (css/style.css) — оставалось с домагазинного дизайна меню (до v1.12).
- Неиспользуемых JS-экспортов, orphaned HTML id, XSS-уязвимостей — не найдено.

### 2. Найденные и исправленные баги (js/combat.js)
1. **Гонка автобоя** — переключение `'normal' → 'fast'` мимо `'off'` планировало второй `setTimeout(autoPlayerLogic)`, не отменяя первый → риск двойного хода. Исправлено: id таймера хранится в `pendingTurnTimeout`, `beginActionPhase()` отменяет его при каждом вызове. Проверено вживую в браузере (принудительно воспроизведена гонка через хук над `setTimeout`/`clearTimeout` — подтверждено, что старый таймер корректно отменяется).
2. **`handleTurnTimeout()`** (поражение по двум пропускам хода подряд) не вызывал `finishBattle()` → промо-герой не снимался с профиля после такого поражения. Добавлен вызов.
3. **`executeSummonAction()`** не потреблял `timeoutDebuff`/`underdogBuff` (единственная из 5 execute-функций) → флаги неверно переносились на следующее действие. Добавлены `applyTemporaryBoosts()/restore()`.

### 3. Живое QA в браузере
- Полный прогон: создание профиля → выбор дружины → бой → победа/поражение/сдача → эпический сундук → промокод (пустой ввод, HTML-инъекция — оба безопасны, без XSS).
- Мобильная вёрстка 375px (меню и бой) — без горизонтального переполнения.
- `npm test` — 57/57 до и после правок.
- `npm run balance` — winrate 48.8–51.6%, среднее 50.0% (баланс не пострадал, изменения не влияли на цифры урона/лечения).
